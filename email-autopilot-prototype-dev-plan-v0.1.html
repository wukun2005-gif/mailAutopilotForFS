01目标与范围

1.1 原型要验证什么

原型不是产品的缩水版，而是 PRD 核心判断的"可反驳证据"。工程上刻意不做的部分与做的部分同等重要。逐条 FR 的覆盖 / 部分 / 不做对照见 §1.5。

原型要证明（做）明确不证明（不做）
  • 未认证公共邮箱也能一次办结低风险件：R0 公共信息任意 I 档 L3，R2 在 I0 也照常建案起钟、只发锁定模板，且全程可审计（屏①）——边界按矩阵格值走，不是一律"要 I3"：R2×I2 与 R2×I3 都是"L2 → 毕业 L3"，预留邮箱 + 三协议通过（I2）且意图已毕业时退费可自动 L3；只有 R2×I1（地址不在档案）判"不放权"改走引导 step-up，R2×I0 内部照常办、对外只发锁定模板
  • 争议件的法定时钟确定性：进件即起钟、48h 预警、临时贷记/裁决人机分界（屏①②③）
  • 放权是"挣来的"：回测 → shadow → 双签毕业，R3/R4 格在配置层不可达（屏④）
  • 长流程中断可续：进程杀掉后从检查点恢复、动作不重复执行（runtime + 屏②③）
  • BEC/ATO 邮件在工具层被拦、对客通知只走 on-file 通道（屏①③）
  • 三类来源拼装的回信：模板字符串 / 系统槽位 / AI 衔接，逐句可溯源（屏①审计视图）
  • live LLM 可在设置屏配置多 provider 并现场切换（仅"一般咨询"彩蛋节点真实调用，失败自动回落录制）
  • 不接真实核心银行、争议系统、邮箱与 OTP 网关——全部由 MSW 返回录制响应
  • 不做多租户、权限体系、真实登录、部署流水线、真实 WORM 存储
  • 不实现真实 conformal prediction 库（FR-3.5 为 P2，证书卡用预制数据演示）
  • 不做真实红队平台（garak/PyRIT 为 Python 生态，不集成；评测用 Node 侧 promptfoo）
  • 不追求像素级复刻 Talkdesk 真实界面，追求"产品判断可被理解"
  • 除一个只读彩蛋节点外，LLM 不参与任何判定与动作；剧本路径演示零随机性（彩蛋可一键锁录制）

02总体架构

单仓单页应用（SPA），无独立后端进程、无 Docker、无数据库安装：浏览器内 MSW 拦截全部业务 API，LangGraph 在浏览器内跑案件状态机，检查点与事件流持久化在 IndexedDB；另有一段寄生在 Vite dev server 内的 middleware BFF（同进程、不增加启动命令）专门托管 LLM provider 设置与 live 调用。一条 npm run dev 启动全部。

2.1 分层架构

L1 UI四个核心屏 + TopBar（语言切换 / 演示控制 / 故障开关）
React 19 + Tailwind v4 + shadcn 风格组件；屏①客户邮件、屏②坐席卷宗、屏③主管台、屏④Builder；审计 Trace Rail 为屏①的视图切换。
L2 演示层Demo Director + FakeCursor + Tooltip（照搬 GraphMe / docStudio，MIT）
数据化脚本（JSON/TS）驱动：播放 / 暂停 / 单步 / 快进 / 重置 / 选剧本 / 跳章节；ESC 中断；找不到元素重试 3 次后跳过并告警。
L3 状态层Zustand stores：caseStore / uiStore / demoStore
案件视图状态、当前屏幕与语言、演示播放状态；store 订阅 runtime 事件流刷新界面；业务状态的唯一权威在 runtime 检查点，store 只做投影。
L4 RuntimeLangGraph JS StateGraph（9 节点）+ 放权闸门 + 政策求值 + 人机断点 + 检查点
@langchain/langgraph：interrupt()/Command(resume) 实现 L1/L2 审批；每个状态迁移产出 CaseEvent；自定义 CheckpointSaver 落 IndexedDB，刷新/杀进程后续跑。
L5 工具网关Tool Registry：白名单签名、幂等键、故障注入开关
所有写动作（退费/起钟/发信/OTP/on-file 通知）只经网关调用；R3/R4 工具在邮件渠道根本不注册（能力层不可达，而非靠提示词克制）；重复 idempotencyKey 返回首次结果。
L6 Mock 层MSW v2（Service Worker 网络拦截）+ fixtures + 虚拟时钟
11 组假 API 返回录制响应；可注入超时 / 500 / 重复投递 / 进程重启；业务时间由 simClock 决定（Day 0 → Day 40 一键快进）。/api/* 与外部请求一律 passthrough，不拦截 Dev BFF。
L7 Dev BFFVite middleware（同进程，仅 npm run dev / preview）：Provider 设置存储 · /models · /verify · LLM 代理
照搬 HarnessWindTunnel：configureServer/configurePreviewServer 挂 /api 路由，node 内置 http 实现、零新依赖；API Key 存本机 server-data/settings.json（原子写、gitignore），服务端注入 Authorization 转发 {baseUrl}/chat/completions，key 不进浏览器 bundle、无 CORS 问题。
横切i18n（react-i18next）· 事件 Trace · Live LLM 彩蛋（Provider 设置屏驱动，单点可降级）
中英双语全量切换；Trace Rail 直接渲染 CaseEvent 流（含模型回退记录 used/switchedFrom）；仅"一般咨询"一个节点经 Dev BFF 调真实 LLM 演示 grounding 与来源标注，未配置 / 超时 / 全链失败时自动回落录制响应。

2.2 一次请求的完整路径（以邮件 1 自主退透支费为例）

1
注入：演示脚本投递一封新邮件
Director 调用 MSW 场景接口写入 fixtures 邮件 → 触发 ingest 节点（真实走图，不是直接跳界面）。
2
triage / identity：录制分类 + 身份保障评定
意图识别在录制模式返回 fixture 结果；I0–I3 闸门按发件地址 / SPF·DKIM·DMARC / 线程信号纯函数计算。
3
policy evaluation：确定性政策求值
OD_FEE_WAIVER_V12 三条件逐条调 mock 核心银行 API 取数、PASS/FAIL 落求值卡；LLM 不参与判定。
4
autonomy decision：L×R×I 三维闸门
闸门返回矩阵格值而非裸 L 级（见 §6.3）；本例（邮件 1 退费）走完 step-up 后为 R2×I3，上线默认 L2、该意图已双签毕业故 L3；动作经工具网关执行（带幂等键），三段拼装生成回信。若在 step-up 之前求值，R2×I1 得到的是"不放权"而不是某个 L 级。
5
close & verify：14 天窗口计时
案件挂起在"待核验"，simClock 快进 14 天无重复接触才计一次 verified resolution（FR-11.5 事件同步产出）。
关键取舍：为什么 runtime 放在浏览器内而不是起 Node 服务 PRD 附录 A 明确"单页应用 + 本地 JSON 事件流持久化"。浏览器内 LangGraph + MSW 让 npm run dev 一条命令即可演示，也让"刷新页面 = 进程重启"成为最自然的中断恢复演示；代价是不做真实并发与多租户——原型阶段不需要。

4.3 五条工程纪律（写进 README 与 AGENTS.md）

  1. 业务时间禁用 new Date() / Date.now()：一律走 simClock.now()，否则跨天剧本（Day 0→45）无法重放，14 天核验窗口也无法演示。唯一例外：trace 里并列记录 wall-clock 仅作调试。
  2. 所有写动作只走工具网关：组件与图节点不得直接 fetch 写接口；R3/R4 工具在 registry 中不存在，从能力层保证"够不到"。
  3. 录制模式零随机性：triage/分类/抽取全部读 fixture；如必须随机（头像抖动等），用固定种子的 mulberry32（约 10 行，注释说明），保证演示与 e2e 每次一致。
  4. provider key 只存在本机 Dev BFF：key 写 server-data/settings.json（.gitignore），由服务端注入 Authorization；不进 bundle、不进 git、不进 CaseEvent/trace/导出；设置屏仅以 password 掩码回填。
  5. 口径只能有一处，改定义必须三方同步：L/R/I 定义、毕业判据、法定时限在 gates.ts、本文档 §1.5/§6.3、PRD §6.2 三处保持一致；改任一处，另两处同一 PR 内跟改，并由 npm run audit:prd 拦截漂移。引用 FR 编号前先在 PRD 里搜到该编号。

  • 重复投递：同一立案请求送达两次 → 动作台账显示 idempotency hit，只产生一条争议记录；
  • 进程重启：在指定节拍 location.reload() → 从 IndexedDB 检查点重建，trace 上打出 HALTED → RESUMED @ node 标记；
  • 时间快进：+1h / +1 工作日 / +1 自然日 / 跳到 Day 6 / bd10（第 10 个工作日 = 10/6，临时贷记到期） / Day 40 / +14 天；
  • 身份降级开关（四个标记，逐一对应 PRD §6.2 I3 的降级规则，与 §12.1 的四条反断言一一对得上）：session-expired 标记核验会话失效（触发 ①，PRD 未定义有效期，属假设分支）｜thread-closed 让 Day 14 的结案真正收尾线程，来信因此落在新线程（触发 ②）｜spoof-signal 注入 FR-2.1 AC3 的仿冒 / 相似性信号，如改发件显示名或用域名变体（触发 ③）｜new-thread 只把第二封放进新线程（触发 FR-2.1 AC2，独立于上述三条）。v0.4另加 no-digital（客户未开通数字银行）：邮件 1 的 step-up 改走一次性链接页，演示 FR-2.2 兜底分支；不影响第二拍。前四个任一打开，邮件 1 第二拍都从"L2 草稿进主管队列"变成"退回 I1 → 命中不放权格 → 不生成正文、只发锁定模板 + 引导 step-up"，屏① Trace 标明这次是被哪一条降级的；
  • 重置场景：清空该剧本的检查点、事件流、幂等台账并重新 seed。
为什么这块值得做：直接回应现网工程痛点 现网反馈"跑着跑着断了、长时间流程端到端连不起来"。原型把中断恢复做成可反复表演的一等场景（不是 PPT 上的一句话）：杀进程、刷新、重复投递都能续跑且动作不重复——这是评委中工程负责人最容易记住的画面。

06玩具 Runtime：LangGraph 案件状态机

runtime 是整个原型的发动机，也是"不造轮子"原则下最依赖现成框架的部分。LangGraph 负责状态机、检查点、人机断点、状态历史；我们只写节点内的业务逻辑与闸门规则。

6.1 图结构：9 节点对齐 PRD 9 步生命周期

1
ingest 进件
去重（线程指纹 + 幂等键）、DLP 预扫、欺诈信号预取；生成 caseId，写首条 CaseEvent。
2
triage & intent 分流与意图
录制模式返回 fixture 意图（含多意图拆分）；置信度低于阈值直接路由 human。
3
identity assurance 身份保障评定
纯函数算 I0–I3，输入六类信号（PRD §6.2 要件逐条对应）：① 发件地址是否在客户档案中（精确匹配预留邮箱，不是只看域名是否同域）；② SPF/DKIM/DMARC 录制结果与 DKIM 与发件域对齐；③ 仿冒变体检测（jane.d0e@ vs 档案 jane.doe@）；④ 欺诈/ATO 信号与档案联系方式近 30 天变更窗口；⑤ 线程内是否已 step-up、是否来自已登录 secure message；⑥ PRD §6.2 I3 的三条降级触发逐条判定——核验会话是否失效、线程是否结束、是否被 FR-2.1 AC3（仿冒 / 相似性）命中，trace 上标明本次是"保持 I3"还是"因哪一条降级"。
4
policy evaluation 政策/资格求值
确定性规则引擎：按意图加载规则包，逐条经工具网关取数，产出条件级求值卡（PASS/FAIL + 证据 + 政策版本）。
5
autonomy decision 放权判定
decideCell(intent, R, I, policyResult, graduationTable) 纯函数返回 CellValue（L 档 / 不放权 / 永不自动，见 §6.3）而非裸 L 级；只在格值为 L 类时才按 L = min(毕业L, 动作允许L, 身份允许L) 定级；单调、fail-closed（任何输入缺失 → L0）。
6
orchestrate & act 编排与动作
按 L 级执行：L3 直接调工具（带幂等键）；L2 起草+人批；L1 起草+人签发；L0 出交接包。每个动作写动作台账。
7
human checkpoint 人机断点
LangGraph interrupt(payload)：案件挂起、进入主管/坐席队列；审批回调 Command(resume) 携带 approve/edit/reject 续跑。

三类		矩阵单元的取值不只有 L0–L3，共三类（PRD §6.2）：① L0–L3，其中"L2 → 毕业 L3"= 上线默认 L2、回测双签后到 L3；② 不放权——发固定模板、引导 step-up，AI 既不生成也不执行内容（R1×I0、R1×I1、R2×I1）；③ 永不自动——配置层禁开、工具层不提供函数（R3 整行）。R2×I0 是复合格：内部建案与起钟照常自动执行，对外回执只发不含账户信息的锁定模板。R4 整行的"永久 L0/L1"属 L 阶梯取值，不是第三类。闸门返回 CellValue 判别联合 {kind:'L'|'deny'|'never'}，不是裸 L 级；屏④ 矩阵、屏③ 审批队列与函数同源

L0–L3		意图必须在毕业表内（受监管 ≥600 触发件且 0 漏检；非受监管 ≥300 且免修改批准率 ≥97%）；仅当格值为第 ① 类时才计算 L = min(毕业L, 动作允许L, 身份允许L)；命中"不放权"或"永不自动"时直接返回该处置，不产出 L 级、也不进审批队列（不需人批：前者发锁定模板或引导 step-up，后者工具层根本不提供函数）。稀有意图 90 天攒不够样本不毕业。L1 = AI 起草人发送；L2 = AI 提案人一键批；L3 = 条件达标后 AI 执行 + 事后抽检。gates.ts 单测全覆盖；矩阵 UI 与函数同源

6.6 虚拟时钟与跨天调度

simClock 是一个可暂停、可跳转的时钟（store + 订阅）：图节点与时钟服务全部读它。两个刻度必须分开，不能混用：dayN = 自然日偏移（Day 6 客户补材料、Day 40 商户凭证到达、Day 45 裁决、+14 天核验）；bdN = 工作日计数，v0.4法定时限按条文各用各的刻度：10 / 20 天是工作日（bd10 = 2026-10-06，临时贷记到期日；新账户分支 bd20），45 / 90 天是日历日（day45 = 2026-11-06，day90 = 2026-12-21，Reg E 1005.11(c)(3)(ii) 原文就是 days 而非 business days）。邮件 2 的 $247.18 是 POS 借记卡交易，适用 90 天分支；45 天节点在时钟条上置灰并注明原因（FR-4.2 AC1“按交易类型自动求值”正好借此演示）。演示日 2026-09-22（周二）起算，节假日表留空按工作日历推算，写死在 simClock.ts 里供单测枚举。跨天事件在场景文件里声明为 {atDay, event}（法定时钟类为 {atBd, event}）；Director 快进时钟时，场景引擎依次投放事件、驱动图继续跑。界面上始终同时显示"模拟日期"与真实录制 wall-time，避免误解。

9.3 播放控制与容错

  • 控制：播放 / 暂停（空格）/ 单步（→）/ 快进倍率（等待类 beat 压缩 ×4，业务动作不跳）/ 重置（清 IndexedDB + 重新 seed + 回主屏）/ 选剧本 / 章节跳转；
  • 容错：找不到 data-id 元素 → 每 300ms 重试、共 3 次 → 仍失败则 console.warn + 记录到 demo 运行报告并跳过该 beat（不中断整场）；requireClick 类关键节拍失败则暂停并提示；
  • 重置即 seed：每次播放前 director.reset(scenarioId)：清 stores、清该剧本 checkpoint/事件流/幂等表、MSW 场景状态归零、simClock 回 Day0、关闭全部故障开关；
  • 语言热切换：播放中切换中/EN，界面与 tooltip 立即换语言，beat 进度不受影响（i18n 是渲染层，不进 state）；
  • reduced motion：跟随系统 prefers-reduced-motion，关闭鼠标滑动动画（直接定位），保留点击与解说。

11.4 调用链与两级回退（逻辑原样移植）

1
选目标 resolveChatTargets
按卡片排序：先「已启用且 key+baseUrl+模型齐全」，其余垫后；可指定 provider/model，否则取链头；判定模型之类的非 chat 卡排除。
2
第一级：同 provider 模型回退
卡上「模型回退」开关开启时，按拖拽顺序形成模型链（默认模型在头、去重）；同一请求逐模型重试。
3
第二级：跨 provider 回退
全局开关开启时，本卡模型链用尽 → 按卡片顺序切下一个可用 provider，再走它自己的模型链。
4
错误分类（照搬）
401 鉴权错＝整链停止（配置错换谁都救不回）；403/429 等 4xx＝不重试直接换目标；5xx/超时/网络错＝同目标退避重试 2 次（500ms、1500ms）再换；HTTP 200 但正文过不了 validate（如 grounding 引用缺失）＝内容级失败，直接换目标。
5
封顶与出处
模型级尝试最多 8 次；单请求超时 120s，AbortSignal 透传；返回 used（实际应答 provider/model）与 switchedFrom（首个失败现场）。
  • 接入彩蛋节点：屏①"一般咨询"线程调 POST /api/llm/chat；used/switchedFrom/usage 写入 CaseEvent，Trace Rail 显示"主模型失败 → 已切换至 X / token 用量"，回退过程本身就是"工程可信"的演示素材；
  • 第三重保险（原型新增，HarnessWindTunnel 没有）：全链失败 / 未配置 provider / Dev BFF 不可达 → 自动回落录制回答并打 recorded 徽标 + Toast 一行提示，界面结构不变、演示不中断；
  • 边界不变：彩蛋节点只挂只读 FAQ 检索（预制 chunk + 关键词，不引入向量库），不注册任何写工具、不读账户明细、不经过放权闸门（R0），更不参与 triage / 闸门 / 政策判定。

11.5 Grounding 呈现与录制/直播标识

  • 回答以 Markdown 渲染（marked + dompurify 先 sanitize）；每个事实句带角标，右栏列来源（虚构政策文档名 + 章节）；系统提示词约束"无来源不输出"，并把"至少包含一个来源角标"写进 validate，校验失败即触发回退；
  • 回答区常驻徽标：LIVE（provider/model） 或 RECORDED；发生回退时显示 LIVE·fallback；故障面板提供「锁定录制模式」开关，开场前可主动关闭一切真实调用。

B附录：术语速查（工程向）

术语白话解释
MSW (Mock Service Worker)用 Service Worker 在浏览器网络层拦截请求的 mock 库；前端代码照常 fetch，收到的是预制响应，还能模拟超时和报错。
Checkpoint / Checkpointer检查点：状态机每走一步自动存一份全量快照；进程死了从最近快照恢复，不用从头来。
interrupt / Command(resume)LangGraph 的人机断点机制：图在需要人审批处挂起，人做完决定后用 resume 带着结果继续跑。
Idempotency key（幂等键）每个写动作的唯一编号；同一编号提交两次，系统只执行一次、第二次回放首次结果——防止"重启后重复退款/重复立案"。
fail-closed（失败即关闭）任何不确定（取不到数、查不到规则、身份不明）都按最低自主权处理（转人），与"先放行再说"的 fail-open 相对。
simClock（虚拟时钟）原型里的假时钟，可一键快进 40 天；所有法定时效计算都读它，保证跨天剧本可重复演示。
fixture预制的假数据样本（客户、邮件、交易、回测结果）。
shadow mode影子模式：AI 给建议但不执行，人按原流程操作，事后比对 AI 建议与人的实际动作，用于毕业前取证。
graduation（毕业）意图从"只能建议"升级到"可自动执行"的门槛流程：回测达标 + 合规与业务双签。
VARRVerified Autonomous Resolution Rate，经核验自主结案率（口径以 PRD §04 为准：无人工触碰 + 14 天无重复接触 + 客户未要求转人 + QA 抽检通过，÷全部有效进件）。
TTR / AHT / ACWTTR = Time to Resolve 结案时长；AHT = Average Handle Time 平均处理时长；ACW = After-Call Work 话后/件后处理时间。
Reg E / Reg Z美国的两条消费者保护条例：Reg E（12 CFR 1005，电子转账差错处理，由 CFPB 颁布）与 Reg Z（12 CFR 1026.13，信用卡账单争议），规定争议受理、临时贷记、裁决的法定时限。
BEC / ATO / SARBEC = Business Email Compromise 仿冒邮件诈骗；ATO = Account Takeover 账户盗用；SAR = Suspicious Activity Report 可疑活动报告。
on-file 通道只向银行档案里已留存的地址/手机号发送通知，绝不回复来信的可疑地址——防 BEC 的基本原则。
grounding模型回答的每句话都能落到给定资料来源上；无来源不输出，防幻觉。
promptfooNode 生态的 LLM/提示词评测 CLI，用断言集批量跑"输入→应满足条件"。
模型回退 / Provider 回退两级 fallback：同一服务商内主模型失败按预设顺序换模型（模型回退）；该服务商模型用尽后按卡片顺序换下一家服务商（Provider 回退）。401 配置错误整链停止，5xx/超时先退避重试。
