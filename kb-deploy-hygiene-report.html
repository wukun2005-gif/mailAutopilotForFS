一个把脚本卡死的环境坑

本机出网走 HTTPS_PROXY。Python 的 urllib 和 curl 都会读这个变量，Node 的 fetch 完全不读——api.siliconflow.cn 直连可达，api.supabase.com 不行。表现是：切块全部跑完、然后在第一次 SQL 调用抛 UND_ERR_CONNECT_TIMEOUT，看起来像代码 bug。已在三个脚本里加 import './net-proxy.mjs' 装 ProxyAgent。

2. 分块卫生：修掉 3 类，其中 1 类是我自己的误报

上一轮加的 --audit 报了 20 处"SVG 残留 + 20 个内部章节 + 16 个过短块"。先让审计打印命中文本再动手——这一步直接改变了结论。

① 内部台账章节被当正文检索 真实缺陷

PRD 的 Review Change Log (v0.3 / v0.2) 16 块、报告的版本记录 20 块、完整参考资料 18 块、勘误 1 块。这些是给文档维护者看的台账，答不了读者的问题，却真的被检索命中——线上实测那条回答的引用来源里就出现了 PRD (English) / Review Change Log。

修法：新增模块级 INTERNAL_HEADING 过滤器，对所有非代码来源生效（不只针对 PRD/dev plan）。修复后审计口径 internal-only 章节 = 0。

② 超长段落硬切留下碎片 真实缺陷

硬切逻辑按固定 1500 字步进，3013 字的段落被切成 1500 / 1500 / 13——最后一块只有 13 字。这种块嵌入出来是噪声，一旦命中就是一段垃圾上下文，实际命中了 report/2.1b …(13)「到端解决；85% 缺编排；」。

修法：按 ceil(len / MAX) 均分，每块都在上限内且不产生退化块。过短块 16 → 13，剩下 13 条全部是合理的短章节（如末页 Thank you. Questions、小节导语、矩阵图例），不再动。

③ "SVG 残留" 是我自己的正则误报 工具问题

原审计正则写了裸词 path|fill，于是把 graduation path、attack path 这类正常英文当成噪声——20 个完全健康的 deck 块被误标。标签本身早在 stripTags 里被剥掉了，真正的残留会是属性（viewBox=、stroke-width=），不会是单词。

修法：改成只匹配 SVG 属性形态。修正后 inline svg residue = 0，deck 干净。
