Email Autopilot for Financial Services
可用性验证原型 · 详细开发计划

依据《Email Autopilot for FS · PRD v0.2》附录 A 编写。目标是用最短路径做出可现场演示、可双语切换、可一键播放的原型：录制式玩具 runtime 驱动真实界面，一个 live LLM 彩蛋，零真实后端、零真实邮件、零真实核心系统。

01目标与范围

1.1 原型要验证什么

原型不是产品的缩水版，而是 PRD 核心判断的"可反驳证据"。工程上刻意不做的部分与做的部分同等重要。

原型要证明（做）明确不证明（不做）
  • 未认证公共邮箱也能一次办结低风险件，且全程可审计（屏①）
  • 争议件的法定时钟确定性：进件即起钟、48h 预警、临时贷记/裁决人机分界（屏①②③）
  • 放权是"挣来的"：回测 → shadow → 双签毕业，R3/R4 格在配置层不可达（屏④）
  • 长流程中断可续：进程杀掉后从检查点恢复、动作不重复执行（runtime + 屏②③）
  • BEC/ATO 邮件在工具层被拦、对客通知只走 on-file 通道（屏①③）
  • 三类来源拼装的回信：模板字符串 / 系统槽位 / AI 衔接，逐句可溯源（屏①审计视图）
  • 不接真实核心银行、争议系统、邮箱与 OTP 网关——全部由 MSW 返回录制响应
  • 不做多租户、权限体系、真实登录、部署流水线、真实 WORM 存储
  • 不实现真实 conformal prediction 库（FR-3.5 为 P2，证书卡用预制数据演示）
  • 不做真实红队平台（garak/PyRIT 为 Python 生态，不集成；评测用 Node 侧 promptfoo）
  • 不追求像素级复刻 Talkdesk 真实界面，追求"产品判断可被理解"
  • 除一个彩蛋节点外，LLM 不参与任何判定与动作，演示零随机性

02总体架构

单仓单页应用（SPA），无后端进程、无 Docker、无数据库安装：浏览器内 MSW 拦截全部 API，LangGraph 在浏览器内跑案件状态机，检查点与事件流持久化在 IndexedDB。一条 npm run dev 启动全部。

2.1 分层架构

L1 UI四个核心屏 + TopBar（语言切换 / 演示控制 / 故障开关）
React 19 + Tailwind v4 + shadcn 风格组件；屏①客户邮件、屏②坐席卷宗、屏③主管台、屏④Builder；审计 Trace Rail 为屏①的视图切换。
L2 演示层Demo Director + FakeCursor + Tooltip（照搬 GraphMe / docStudio，MIT）
数据化脚本（JSON/TS）驱动：播放 / 暂停 / 单步 / 快进 / 重置 / 选剧本 / 跳章节；ESC 中断；找不到元素重试 3 次后跳过并告警。
L3 状态层Zustand stores：caseStore / uiStore / demoStore
案件视图状态、当前屏幕与语言、演示播放状态；store 订阅 runtime 事件流刷新界面；业务状态的唯一权威在 runtime 检查点，store 只做投影。
L4 RuntimeLangGraph JS StateGraph（9 节点）+ 放权闸门 + 政策求值 + 人机断点 + 检查点
@langchain/langgraph：interrupt()/Command(resume) 实现 L1/L2 审批；每个状态迁移产出 CaseEvent；自定义 CheckpointSaver 落 IndexedDB，刷新/杀进程后续跑。
L5 工具网关Tool Registry：白名单签名、幂等键、故障注入开关
所有写动作（退费/起钟/发信/OTP/on-file 通知）只经网关调用；R3/R4 工具在邮件渠道根本不注册（能力层不可达，而非靠提示词克制）；重复 idempotencyKey 返回首次结果。
L6 Mock 层MSW v2（Service Worker 网络拦截）+ fixtures + 虚拟时钟
11 组假 API 返回录制响应；可注入超时 / 500 / 重复投递 / 进程重启；业务时间由 simClock 决定（Day 0 → Day 40 一键快进）。
横切i18n（react-i18next）· 事件 Trace · Live LLM 彩蛋（AI SDK，单点可降级）
中英双语全量切换；Trace Rail 直接渲染 CaseEvent 流；仅"一般咨询"一个节点可接真实 LLM 演示 grounding 与来源标注，无 key / 超时 / 报错时自动回落录制响应。

2.2 一次请求的完整路径（以邮件 1 自主退透支费为例）

1
注入：演示脚本投递一封新邮件
Director 调用 MSW 场景接口写入 fixtures 邮件 → 触发 ingest 节点（真实走图，不是直接跳界面）。
2
triage / identity：录制分类 + 身份保障评定
意图识别在录制模式返回 fixture 结果；I0–I3 闸门按发件地址 / SPF·DKIM·DMARC / 线程信号纯函数计算。
3
policy evaluation：确定性政策求值
OD_FEE_WAIVER_V12 三条件逐条调 mock 核心银行 API 取数、PASS/FAIL 落求值卡；LLM 不参与判定。
4
autonomy decision：L×R×I 三维闸门
意图已毕业 + R2 + I2 → L3；动作经工具网关执行（带幂等键），三段拼装生成回信。
5
close & verify：14 天窗口计时
案件挂起在"待核验"，simClock 快进 14 天无重复接触才计一次 verified resolution（FR-11.5 事件同步产出）。
关键取舍：为什么 runtime 放在浏览器内而不是起 Node 服务 PRD 附录 A 明确"单页应用 + 本地 JSON 事件流持久化"。浏览器内 LangGraph + MSW 让 npm run dev 一条命令即可演示，也让"刷新页面 = 进程重启"成为最自然的中断恢复演示；代价是不做真实并发与多租户——原型阶段不需要。

03技术选型：能装就不造，能买就不写

原则：基础设施一律用成熟库，自己只写业务判断（放权矩阵、政策规则、剧本数据、界面、演示脚本）。下列版本均为 2026-09-28 从 npm registry 实查；license 全部为 MIT / Apache-2.0 / ISC / MPL 双许可，零 copyleft 风险。

5.3 故障注入控制台（TopBar 开发者面板，演示时可手点也可脚本触发）

  • 连接器超时：下一个核心银行请求延迟 8s 后失败 → 演示重试与降级；
  • 重复投递：同一立案请求送达两次 → 动作台账显示 idempotency hit，只产生一条争议记录；
  • 进程重启：在指定节拍 location.reload() → 从 IndexedDB 检查点重建，trace 上打出 HALTED → RESUMED @ node 标记；
  • 时间快进：+1h / +1 工作日 / 跳到 Day 6 / Day 10 / Day 40 / +14 天；
  • 重置场景：清空该剧本的检查点、事件流、幂等台账并重新 seed。
为什么这块值得做：直接回应现网工程痛点 现网反馈"跑着跑着断了、长时间流程端到端连不起来"。原型把中断恢复做成可反复表演的一等场景（不是 PPT 上的一句话）：杀进程、刷新、重复投递都能续跑且动作不重复——这是评委中工程负责人最容易记住的画面。

06玩具 Runtime：LangGraph 案件状态机

runtime 是整个原型的发动机，也是"不造轮子"原则下最依赖现成框架的部分。LangGraph 负责状态机、检查点、人机断点、状态历史；我们只写节点内的业务逻辑与闸门规则。

6.1 图结构：9 节点对齐 PRD 9 步生命周期

1
ingest 进件
去重（线程指纹 + 幂等键）、DLP 预扫、欺诈信号预取；生成 caseId，写首条 CaseEvent。
2
triage & intent 分流与意图
录制模式返回 fixture 意图（含多意图拆分）；置信度低于阈值直接路由 human。
3
identity assurance 身份保障评定
纯函数算 I0–I3：发件域与档案域名匹配、SPF/DKIM/DMARC 录制信号、线程历史、step-up 状态。
4
policy evaluation 政策/资格求值
确定性规则引擎：按意图加载规则包，逐条经工具网关取数，产出条件级求值卡（PASS/FAIL + 证据 + 政策版本）。
5
autonomy decision 放权判定
decideL(intent, R, I, policyResult, graduationTable) 纯函数输出 L0–L3 与理由码；单调、fail-closed（任何输入缺失 → L0）。
6
orchestrate & act 编排与动作
按 L 级执行：L3 直接调工具（带幂等键）；L2 起草+人批；L1 起草+人签发；L0 出交接包。每个动作写动作台账。
7
human checkpoint 人机断点
LangGraph interrupt(payload)：案件挂起、进入主管/坐席队列；审批回调 Command(resume) 携带 approve/edit/reject 续跑。
8
respond 对客回复
三段拼装（模板字符串 / 系统槽位 / AI 衔接句），逐段带来源标注；L1/L2 邮件只存草稿不自动发；DLP 终扫。
9
close · verify · learn 结案/核验/学习
挂"待核验"，14 天（约 10 个工作日）无重复接触且 QA 抽检通过才计 verified resolution；事件同步 FR-11.5；结果回流毕业计数。

9.2 Scenario Director：为什么不能只靠假鼠标点 UI

三封邮件里有跨天、等审批、等故障的节拍（Day 6 材料到达、Day 10 审批、Day 40 凭证、进程重启）。FakeCursor 只能点界面，无法让"40 天后的事件发生"。因此分两层：

A
Director（无 UI，驱动系统）
解释 Beat 脚本：event/clock/fault/goto/wait 直接调用 store action、runtime 注入接口、simClock、faultController；它是"世界的导演"。
B
FakeCursor（有 UI，模拟人）
只处理 cursor 与 tooltip：移动、点击、输入、解说；它是"观众的眼睛"。审批按钮的点击也由它真实触发（而非 director 代批），保证人机断点是真人动作路径。
C
桥接（useDemo）
GraphMe 同款 CustomEvent → React 桥：FakeCursor 与 Director 通过 demoStore 同步（当前 beat、暂停态）；暂停时两边都停；单步 = 执行一个 beat 后暂停。

9.3 播放控制与容错

  • 控制：播放 / 暂停（空格）/ 单步（→）/ 快进倍率（等待类 beat 压缩 ×4，业务动作不跳）/ 重置（清 IndexedDB + 重新 seed + 回主屏）/ 选剧本 / 章节跳转；
  • 容错：找不到 data-id 元素 → 每 300ms 重试、共 3 次 → 仍失败则 console.warn + 记录到 demo 运行报告并跳过该 beat（不中断整场）；requireClick 类关键节拍失败则暂停并提示；
  • 重置即 seed：每次播放前 director.reset(scenarioId)：清 stores、清该剧本 checkpoint/事件流/幂等表、MSW 场景状态归零、simClock 回 Day0、关闭全部故障开关；
  • 语言热切换：播放中切换中/EN，界面与 tooltip 立即换语言，beat 进度不受影响（i18n 是渲染层，不进 state）；
  • reduced motion：跟随系统 prefers-reduced-motion，关闭鼠标滑动动画（直接定位），保留点击与解说。

9.4 演示防腐：把"剧本不腐烂"写进 CI

每个 demo 脚本一个 Playwright 用例 npm run e2e 无头执行五个脚本：director 跑完后断言①无 requireClick 失败、②关键 data-id 全部被命中过、③每章结束时屏幕关键元素存在（如邮件 3 结束时隔离卡可见）、④无 console error。任何 UI 重构改坏演示，提交前即暴露。另写一个 data-id 清单测试：脚本引用的 id 必须在源码中存在（GraphMe 后期靠人工维护，这里制度化）。

11Live LLM 彩蛋：一个节点，三重保险

PRD 附录 A 要求"一个 live 彩蛋：一般咨询接真实 LLM 演示 grounding 与来源标注，其余录制"。它的定位是证明工程接入能力，不是产品主张的证据，因此必须保证：没有它，演示照常 100% 跑完。

设计点做法
唯一入口屏①增加一个"一般咨询"样例线程（如"你们的 wire transfer cut-off time 是几点？"）；仅该线程的 answer 节点调 AI SDK streamText，工具只挂只读知识库检索（fixture FAQ 向量检索可用关键词/嵌入二选一，原型用预制 chunk + 关键词即可，不引入向量库）
Grounding 呈现回答以 Markdown 流式渲染（marked + dompurify sanitize）；每个事实句带角标，侧栏列来源段落（政策文档名 + 章节，虚构）；无来源支撑的句子不允许出现（提示词约束 + 录制演示脚本）
三重保险①无 VITE_LLM_API_KEY → 直接用录制回答并打"recorded"小标；②请求 8s 超时 / 报错 / 限流 → 自动回落录制回答，Toast 一行提示；③现场网络受限 → 开场前可用故障面板手动锁录制模式。三种情况界面结构完全一致
安全边界彩蛋节点不注册任何写工具、不接触客户账户数据、不经过放权闸门（R0 只读）；提示词与工具清单写进 README，避免被误解为"autopilot 靠 LLM 自由发挥"
ProviderAI SDK 7 + @ai-sdk/openai（Apache-2.0）；base URL / model 走 env，方便换任何 OpenAI 兼容端点；key 只在本地 .env.local，不提交、不打进构建说明之外的任何地方

B附录：术语速查（工程向）

术语白话解释
MSW (Mock Service Worker)用 Service Worker 在浏览器网络层拦截请求的 mock 库；前端代码照常 fetch，收到的是预制响应，还能模拟超时和报错。
Checkpoint / Checkpointer检查点：状态机每走一步自动存一份全量快照；进程死了从最近快照恢复，不用从头来。
interrupt / Command(resume)LangGraph 的人机断点机制：图在需要人审批处挂起，人做完决定后用 resume 带着结果继续跑。
Idempotency key（幂等键）每个写动作的唯一编号；同一编号提交两次，系统只执行一次、第二次回放首次结果——防止"重启后重复退款/重复立案"。
fail-closed（失败即关闭）任何不确定（取不到数、查不到规则、身份不明）都按最低自主权处理（转人），与"先放行再说"的 fail-open 相对。
simClock（虚拟时钟）原型里的假时钟，可一键快进 40 天；所有法定时效计算都读它，保证跨天剧本可重复演示。
fixture预制的假数据样本（客户、邮件、交易、回测结果）。
shadow mode影子模式：AI 给建议但不执行，人按原流程操作，事后比对 AI 建议与人的实际动作，用于毕业前取证。
graduation（毕业）意图从"只能建议"升级到"可自动执行"的门槛流程：回测达标 + 合规与业务双签。
VARRVerified Autonomous Resolution Rate，经核验自主结案率（口径以 PRD §04 为准：无人工触碰 + 14 天无重复接触 + 客户未要求转人 + QA 抽检通过，÷全部有效进件）。
TTR / AHT / ACWTTR = Time to Resolve 结案时长；AHT = Average Handle Time 平均处理时长；ACW = After-Call Work 话后/件后处理时间。
Reg E / Reg Z美国美联储条例 E（电子转账错误/卡争议）与条例 Z（信用卡计费争议），规定争议受理、临时贷记、裁决的法定时限。
BEC / ATO / SARBEC = Business Email Compromise 仿冒邮件诈骗；ATO = Account Takeover 账户盗用；SAR = Suspicious Activity Report 可疑活动报告。
on-file 通道只向银行档案里已留存的地址/手机号发送通知，绝不回复来信的可疑地址——防 BEC 的基本原则。
grounding模型回答的每句话都能落到给定资料来源上；无来源不输出，防幻觉。
promptfooNode 生态的 LLM/提示词评测 CLI，用断言集批量跑"输入→应满足条件"。
τ²-benchSierra 开源的跨系统 agent 评测基准；本原型只借鉴任务构造方法，不集成代码。
