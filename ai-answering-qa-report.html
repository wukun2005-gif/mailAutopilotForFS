3. 发现并修复的缺陷

严重 并发下同一条评论被回答两次

影响：评论落库瞬间触发器就发起回答；若此时再有第二次调用（重试、人工触发、webhook 重放），幂等检查只看「是否已 sent」，于是看到 running 就放行 → 同一评论下挂了两条 AI 回答。

证据：实测调用两次后 select count(*) from deck_comments where parent_id=… and author='Deck AI' 返回 2（应为 1）。

修复：改为原子抢占 —— 用 on_conflict=comment_id + resolution=ignore-duplicates 插入，让主键决定谁干活，抢不到的立即退出（already running）；只有 failed 允许被接管重试。复验：制造并发后条数 = 1 ✓

中 owner 面板打不开（CORS）

影响：面板一直显示「Failed to fetch」，owner 无法配置。

根因：deck-admin 是唯一被浏览器直接调用的函数（另外两个都是服务端调用），而它没有返回跨域头，也没有处理 OPTIONS 预检。

修复：加 CORS 头与预检处理。通配来源是安全的 —— 每个动作仍需服务端校验 owner 密钥。

中 一批模型「免费额度用尽」，白白拖慢回答

影响：默认模型 qwen-plus 返回 403 Free quota exhausted，回退链每次都要先撞一遍 403（每次 2–4 秒），首次实测耗时 46.9 秒。

修复：实测 10 个模型后重建回退链 —— 把 5 个已耗尽额度的模型整个移除，主模型改为 deepseek-v4-flash-0731（约 3 秒、几乎不产生推理 token）。耗时降到 21–28 秒。

轻 回答被截断 + embedding 批次被拒

输出上限 700 token 时，推理模型的「思考」也计入预算，回答在句中断掉 → 提高到 1600。
embedding 网关单批上限是 20 条（patentExaminator 那边用 100），按 100 提交直接 400 → 改为 20。

轻 AI 的回答会给 owner 多发一封邮件

AI 回答本身也是一条新评论，会再触发一次 owner 通知 —— 每条读者评论让 owner 收两封。已在 notify-reply 里跳过 Deck AI 的署名。复验：AI 回答产生 0 条通知记录 ✓

严重 ⑥ 回答偶发为空 —— 思考吃光了输出预算

症状：中文提问约一半概率返回空正文，函数据此认为「模型失败」并回退到备选模型，于是同一条评论有时 6 秒、有时 42 秒，看起来像模型不稳定。

真因（抓完整响应后确认）：这些模型默认先推理再作答，推理内容写在 reasoning_content、并计入 max_tokens。设成 800 时，一次提问能产生 1400–3600 个思考 token，预算被吃光，finish_reason=length 而 content 为空。全英文提问同样会触发，与语言无关。

修复：请求里加 enable_thinking: false。推理 token 归零，同样问题 3 秒出结果（原 5–25 秒），空回答消失。实测 6/6 成功、无回退。

中 ⑦ 语言策略：从「固定英文」改为「跟随提问语言」

起因：关掉思考后模型会镜像刚读到的语言 —— 中文提问有约 1/3 得到中文回答，与最初的「回答固定英文」要求冲突。

处理：先按原要求修（语言规则移到 system prompt 末尾 + 程序化语言校验 + 必要时重试，实测 6/6 全英文）。随后 owner 改了口径：回答应当跟随提问语言。于是移除强制英文与校验重试，system prompt 改为「中文问用中文答、英文问用英文答」，产品术语、条款号与页面标题保留英文原样（deck/PRD/报告都是英文，翻译过的术语读者反而无从对照）。复验：中文提问 2/2 得中文、英文提问 2/2 得英文，平均 6.9 秒。

轻 ⑧ owner 识别从「URL 密钥」改为「URL 参数」

owner 认为每次带密钥太麻烦，改为 ?config=true 打开一次即记住，服务端不再校验密钥。这是「藏起来」而不是「锁起来」：知道参数的人就能打开面板改设置（影响面有限：开关 AI、换模型）。密钥仍保留在项目里（Secrets 的 OWNER_KEY），要收回时把校验加回 deck-admin 即可。

5. 未覆盖 / 残留风险

  • 中文提问的检索质量：知识库以英文为主（PRD 中文按要求排除），中文 query 的向量相似度只有 0.4 左右。回答仍然可用（跨语言召回 + 生成），但不如英文提问精准。升级路径：查询改写（先译成英文再检索）或引入 rerank 模型。
  • 无成本护栏：评论被恶意刷会等比消耗 LLM 额度。当前靠 owner 面板手动关闭；未实现限流。
  • 回答延迟 20–30 秒：异步执行、读者不阻塞，但刷新页面后要等一会儿才看到回答。未做「正在生成中」的占位提示。
  • 知识库需手动重建：文档更新后要跑 node scripts/kb-ingest.mjs，未接入自动化。
  • 未做幻觉率评估：三次抽测都带正确引用，但没有系统性的 groundedness 打分（patentExaminator 有 LLM-as-Judge 校验，本项目未移植）。
